# Viele checkout integrity deployment

The application requires `supabase/migrations/202609220001_viele_checkout_integrity.sql`.
The migration is provided for review and has **not been applied** by this change.

1. Verify the current Viele header/detail schema against the explicit INSERT columns in the migration, including generated-column metadata and constraints. Apply the migration to a development or staging database first.
2. Run a real transactional smoke test using a temporary draft with one line; verify both records, then delete that draft and its cascading detail. Test a deliberately invalid detail and verify that no header remains. Test two simultaneous claims for one test store and confirm exactly one owner. Remove only the identified test claim records.
3. Deploy the migration through the normal Supabase process before the application. Live checkout fails closed with HTTP 503 when the durable claim RPC is missing. Draft saving also requires the atomic persistence RPC.
4. Deploy the application and verify read-only history plus local simulation. Simulation does not contact V&S and does not prove checkout acceptance by V&S.

Request keys default to a stable hash of the canonical capture, store and delivery date. Clients may supply a persistent `Idempotency-Key` per user-confirmed purchase attempt. Reuse the same key for retries; changing its payload is rejected. A completed key replays the saved response, never resubmits.

Interrupted or unverified requests remain `processing` or `recovery_required` and keep a store-wide lock. They never expire automatically: the V&S cart belongs to the store, not to an individual request. An operator must reconcile the provider's order history and the request `result.recoverySnapshot`, restore missing local records if necessary, and mark that exact request completed with its reconciled response before allowing further checkout. Do not clear a lock or generate a fresh key merely to retry an uncertain submission.

Orders whose official totals or detail could not be verified use `reconciliation_required`; zero in a local draft is only a storage placeholder and `taxPending: true` marks tax as unknown. No fixed percentage is estimated.

Validation performed locally: production validators and TypeScript. The required live database smoke test remains pending until the migration is applied to an authorized test database. No supplier orders were generated by validation.
